## Plan 1.1-1.2: getById ([PLAN-1.1-1.2-GETBYID.md](PLAN-1.1-1.2-GETBYID.md))

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-05 | `#` and `id=` prefix stripping is removed, `normalizeIdValue` is deleted, and the string is matched verbatim and case-sensitively. | Makes ids starting with `#` or `id=` reachable, matches the `getByTestId` convention, and removes the triple normalisation from analysis 1.10. |
| 2026-10-05 | No registration-time guard against a leading `#` or `id=`. | A guard would reintroduce the blind spot being removed. A stale call site fails visibly, with the rendered selector and the registry path in the message. |
| 2026-10-05 | An empty id throws at registration via `assertIdValue`. The message names the registry path, or `createReusable.getById` for reusable seeds. | Fail fast at the boundary instead of a `TypeError` at resolution. |
| 2026-10-05 | Whitespace inside ids is escaped, not rejected. | HTML ids may contain spaces, and the attribute selector handles them. |
| 2026-10-05 | `cssEscape` is deleted together with `normalizeIdValue`. | Not exported from the package root; replaced by the new `escapeCssString` and `buildIdSelector` helpers. |
| 2026-10-05 | The registration builder distinguishes `undefined` (inherit, seeded only) from a value with an explicit `=== undefined` check. A non-seeded `getById(undefined)` throws. `applyDefinitionPatch` keeps the id case as `patch.id !== undefined ? patch.id : base.id`. | Truthiness checks conflated an empty string with "not provided". |
| 2026-10-05 | `createLocator` throws a descriptive error when an id definition lacks an id, instead of `?? ""`. | Surfaces a corrupted definition instead of producing an empty selector. |
| 2026-10-05 | No change to `IdDefinition` or any exported type. No signature change. | The contract change is behavioural; stable types keep the migration to call-site values. |
| 2026-10-05 | New integration coverage asserts against real DOM elements, not only against `toString()`. | The 2.x suite passed while the selector was broken because it only compared rendered strings. |
| 2026-10-06 | Ships in 3.0.0 as `major`; doc edits land under `docs/v3`. | See the process table. |
| 2026-10-06 | String ids resolve as `[id="…"]` with a CSS string escape covering `"`, `\`, LF, CR and FF (`\a `, `\d `, `\c `). NUL is left as is, since no CSS selector can express it. | Attribute selectors accept any string value, and `#` needs identifier escaping, which was broken. A raw CR or FF inside a CSS string is a `BADSTRING` parse error (Chromium probe). |
| 2026-10-06 | `getById(RegExp)` resolves through Playwright's `internal:attr=[id=/source/flags]` engine. Rejected: a `match` option over CSS attribute operators plus throwing on regex metacharacters, which would give up the pattern use case. | It is the engine `getByTestId(RegExp)` compiles to, so it cannot disappear quietly; the selector string is built in one helper; integration tests resolve real elements through it, so a Playwright change fails CI loudly. |
| 2026-10-06 | The tricky-id fixture is a new `/testids` express route with its own page object, fixture and spec. The static W3 index page stays untouched. | Keeps the fixture readable and isolated; follows the existing `/testfilters` and `/iframe` layout. |
| 2026-10-06 | Unit tests run on vitest, colocated as `src/**/*.test.ts`, with `vitest.config.ts` limiting discovery to that glob. Rejected: `node:test` with `tsx`, and a separate `unit/` folder. | Pure helpers need no browser and the inner loop should be milliseconds. Verified that test files cannot ship: tsup bundles from `index.ts` only, and `pnpm pack` publishes only the `files` allowlist (`dist/**`, README, LICENSE, CHANGELOG). |
| 2026-10-06, amended 2026-10-12 | All RegExp flags pass through to Playwright unchanged, including sticky `y`, which is a deterministic start anchor on the 3.0.0 floor; the docs carry no version caveat. | Playwright fixed the `lastIndex` carry-over in [microsoft/playwright#42818](https://github.com/microsoft/playwright/pull/42818) (merged 2026-09-22, first release 1.64.0, verified empirically on 2026-10-12: `getByText(/foo/g)` matched 5 of 9 elements on 1.62.1 and 9 of 9 on 1.64.0). With the floor at 1.64.0 (plan 1.6-1.8) the earlier "deterministic on 1.64 and later, unreliable before" wording is gone. Replaces the 2026-10-06 row, whose rationale was keeping `getById` identical to `getByTestId` on every Playwright version. |

## Plan 1.3-1.4: URL composition and navigation ([PLAN-1.3-1.4-URL-NAVIGATION.md](PLAN-1.3-1.4-URL-NAVIGATION.md))

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-07 | Design principle: URL handling behaves exactly like Playwright's `baseURL` handling, with one addition, a `baseUrl` per page object. Extended 2026-10-08 to timeouts and load states: POMWright sets no timeout or `waitUntil` default of its own; each Playwright call keeps what its config option gives it (`use.navigationTimeout` for `page.goto` and `page.waitForURL`), overridable through method options. | POMWright should feel like a natural extension of Playwright; several bases per project is the only intended difference. A library default would silently override the project's Playwright config. |
| 2026-10-07 | String `fullUrl` and `goto` targets are resolved with `new URL(input, baseUrl)`. No prefix joining. | With an origin-only base and a `/`-rooted path, `new URL` and prefix joining agree, and `new URL` is what Playwright does for `page.goto`. |
| 2026-10-08 | A string `baseUrl` is a non-empty origin (`scheme://host[:port]`, optional trailing slash): no path, query, hash, scheme-less, or empty value. The parameter is a plain `string`, checked at construction by an internal `assertBaseUrl` (non-empty host, pathname `/`, no search or hash) with the class label in the message. Compile-time literal types were tried and dropped: they catch only malformed literals, which the runtime check catches at the same point (fixture setup), and they force every environment-driven value through a narrowing call. | Playwright accepts a base path but `new URL` drops it for every `/`-rooted path and keeps it only for an empty path; rejecting it removes that trap. `localhost:9000` parses as scheme `localhost` with no host and cannot resolve paths in Playwright either (verified; 2.1.0 navigated only through browser URL fix-up, and every URL assertion then failed). A required argument must not silently fall back to the config `use.baseURL`; every supported layout passes an explicit base. |
| 2026-10-08 | A string `urlPath` is `""` or starts with exactly one `/`. The parameter is a plain `string`, checked at construction by an internal `assertUrlPath`. Nothing new is exported for URLs except `UrlMatcher`. Supersedes the `"" \| string` question (identical to `string`, verified with `tsc`). | A leading `//` is protocol-relative under `new URL` and would change host; a genuine `//` path is reachable through a RegExp path. Same reasoning as the base row for dropping the literal types. |
| 2026-10-07 | `goto()` without an argument replaces `gotoThisPage()`, runs the post-navigation actions, and accepts `runPostNavigationActions: false` (name may change at execution). `goto(target)` never runs the actions and has no actions option; a target equal to `fullUrl` is ordinary navigation, undetected. `gotoThisPage` is removed. `expectThisPage` accepts the same option. | Called on the page object, `goto()` says as much as `gotoThisPage()`; one method with one rule. Verified with `tsc` that the no-argument overload exists only for a string `fullUrl` and the option only on that form. |
| 2026-10-07 | `goto(target)` is always available. On a string base any Playwright-accepted input is resolved against the page object's origin; on a RegExp base the target is typed `` `${string}:${string}` `` and a non-absolute input throws at runtime. | Parity with `page.goto` under `use.baseURL`; a RegExp base has nothing to resolve a path against. |
| 2026-10-08 | `expectThisPage` is one `page.waitForURL(matcher, { waitUntil, timeout })` call, then the actions; Playwright's timeout error is rethrown with the label, the expected URL or matcher, the found URL (read at failure time), and the original error as `cause`. Replaces the `toHaveURL` plus `waitForLoadState` design decided on 2026-10-07. | `waitForURL` is Playwright's documented navigation wait and obeys `use.navigationTimeout`; when the URL already matches it waits for the requested load state of the current document (source verified), so `toHaveURL` and a separate `waitForLoadState` were redundant. The replaced design bound a navigation wait by `expect.timeout` (a slow navigation that 2.x tolerated under the navigation timeout failed at 5 s) and summed the ceilings of three calls. |
| 2026-10-08 | `expectAnotherPage` is one `page.waitForURL(url => !matcher(url), { waitUntil, timeout })` call followed by an immediate, non-waiting re-check that fails if the URL bounced back. It is the exact negation of `expectThisPage`: a string page's identity is its exact URL, so a new query counts as another page for both methods. Replaces the three-step design of 2026-10-07. | One waiting call, one ceiling; the re-check catches a redirect that returned (verified against a 200 ms bounce); an asymmetric query rule would leave a URL that fails both methods. |
| 2026-10-08 | `NavigationOptions` is `{ waitUntil?, timeout? }`; the 2.x `waitForLoadState` option is removed, and the 2.x `"load"` constants go. Both options resolve per call, then from the page object's `navOptions`, then to Playwright's defaults. | `waitForLoadState` existed only for `expectAnotherPage`'s separate load-state call, which no longer exists; `waitUntil` is its superset. |
| 2026-10-07 | When either part is a RegExp, `fullUrl` is a structured `UrlMatcher` (exported): the base is tested against `url.origin`, the path against `pathname + search + hash`; string parts are exact; RegExp parts run as written with their own flags; no anchors are added, removed, or rewritten. It is a predicate accepted by `waitForURL` and `toHaveURL` (predicate form since Playwright 1.51, inside the peer range) and carries `.base`, `.path`, `.test()`, `toString()`. Rejected: a single composed RegExp with a `[^/]*` filler, and a `RegExp` subclass. | Concatenating two regexes forces the base to match up to the exact character where the path starts, so a substring base never matched; the URL parser already provides the seam. Removes anchoring, wrapping, flag-merging, escaping, and seam rules. A `RegExp` subclass does not work because Playwright serialises source and flags. Verified in Chromium for all four type combinations. |
| 2026-10-07 | Consumer impact of the `UrlMatcher` type: `expect(url).toMatch(poc.fullUrl)` becomes `expect(page).toHaveURL(poc.fullUrl)` or `poc.fullUrl.test(url)`; `.source`/`.flags` become `.base`/`.path`; a base regex matches the origin only, so path prefixes move to `urlPath`. Nothing in the repository breaks: the harness's `page.goto(x.fullUrl)` calls are on string pages and its `waitForURL(this.fullUrl)` calls accept a predicate. | Inventoried every `fullUrl` use in `src`, `test`, and `docs/v3` on 2026-10-07. |
| 2026-10-07 | No ignore-query option. Pages whose identity includes a query are RegExp page objects with their own navigation method. | Keeps one semantic, identical to Playwright's `toHaveURL`; revisit only if real suites fill with `(\?.*)?$`. |
| 2026-10-07 | New `src/helpers/url.ts` with colocated unit tests; new `/testnav` fixture route, `testnav` and `testnav-item` page objects, and a construction-time validation spec. | Same structure as plan 1.1-1.2. |
| 2026-10-07 | The unit tests' type-level assertions (`expectTypeOf`, `@ts-expect-error`) are enforced by vitest typecheck mode, enabled in `vitest.config.ts` for `src/**/*.test.ts`; `vitest` is pinned exactly to `5.0.3`. The repo-wide `tsc --noEmit` step remains an analysis section 4 item. | Nothing in the repo runs `tsc`, so without this a loosened type passes CI silently. Verified 2026-10-07 that the mode reports an unused `@ts-expect-error` as a failing test against the current source. Vitest labels the mode experimental and asks for an exact pin. |

## Plan 1.5: session storage ([PLAN-1.5-SESSION-STORAGE.md](PLAN-1.5-SESSION-STORAGE.md))

| Date | Decision | Why |
| --- | --- | --- |
| 2026-10-09, amended 2026-10-12 | `SessionStorage` is rebuilt on Playwright's `page.sessionStorage` (WebStorage API, 1.61). Rejected: keeping the `>=1.57.0` floor with a `page.evaluate` fallback. The floor this set, `>=1.61.0`, is superseded by `>=1.64.0` (plan 1.6-1.8 section). | One code path; the 1.57 floor is never exercised (analysis section 4). A fallback would be two implementations to keep identical for a version nobody runs. |
| 2026-10-09 | Values are strings by default, stored and returned verbatim. Structured values are declared once per key through a `schema` of codecs (`{ parse, stringify }`); `json<T>()` ships, `Codec<T>` and `SessionStorageSchema` are exported; an undeclared key must be a string at compile time and at runtime; a declared key whose stored value fails its codec throws naming the key. No parser beyond JSON is added. Rejected: a per-call `{ json: true }` option; 2.1's heuristic parse. | The right encoding of a string depends on the app's storage layer (an `ngx-webstorage` app wants quoted JSON strings, a raw-token app does not), so no heuristic can serve both and 2.1's fallback turned `"01234"` into `1234`. A per-call flag was prototyped and could not decode a mixed store (the all-entries read failed with `token: "abc"` beside JSON values), needed a generic at every call, and could not check key names. A declared schema handles mixed keys in one call, checks names and shapes where they are written, and matches how POMWright treats locators. Verified with a tsc 5.9.3 prototype under strict settings. |
| 2026-10-09 | `get(keys)` returns `null` for a missing key; `get()` returns present entries, declared keys decoded. | Mirrors `getItem` and `items()`. |
| 2026-10-09 | A literal `[]` on `get` and `clear` is a compile-time error through a `NonEmpty<K>` constraint; a computed empty list returns `{}` or removes nothing. Rejected: "empty means all" (2.1), and throwing at runtime. | A literal `[]` is a mistake and the check costs nothing (prototype-verified: `string[]`, `readonly string[]` and `as const` tuples still pass). Mapping no keys over `getItem` is no calls; throwing would force callers to special-case lists derived from data. |
| 2026-10-09 | Method names stay `set`, `get`, `clear`, `seed`, each taking a single key or a record: `set(key, value)`, `get(key)`, `clear(key)`, `seed(key, value, options?)` beside the record forms. Rejected: mirroring `getItem` / `setItem` / `removeItem` / `items` one to one. | The helper's value is the batch form, the step titles, the origin checks, the codecs and `seed`; a one-to-one mirror would duplicate `page.sessionStorage`, which is available to anyone who wants it, and `items` is a poor name. The 2.x names keep the migration mechanical. |
| 2026-10-09 | A helper constructed with an origin (every page object with a string `baseUrl`) throws from `set`, `get` and `clear` when the page is on another origin, naming both origins and the fix; `seed` is exempt; a helper without an origin operates on the current origin. | Another origin's session storage is reachable only from a document on it, so the only alternative is a silent read of the wrong origin. Verified: entries of an origin persist in the tab across cross-origin navigations and are invisible from the other origin. |
| 2026-10-09 | `waitForContext` is removed; an operation on a page without an origin fails at once with a message naming the fix and Playwright's `SecurityError` as `cause`. | Playwright itself throws on `about:blank`; 2.1's wait had no timeout (1.5g). |
| 2026-10-09 | The `reload` option of `set` is removed. | Navigation belongs to the test or the navigation helper; the replacement is one line. |
| 2026-10-09, amended 2026-10-10 | `PageObject` names the storage schema type through an optional `storage` member of its existing `UrlTypeOptions` bag, read by `StorageTypeFromOptions`, takes a `sessionStorage: { schema }` constructor option, and passes `{ label, origin, schema }` to the helper, `origin` being the string `baseUrl`'s origin. Replaces the third generic decided on 2026-10-09. Renaming `UrlTypeOptions` is left to plan 7. | TypeScript cannot skip generics, so a third one would have forced every subclass with a schema to spell out the URL defaults. Verified with `tsc`: `storage` alone keeps the string URL defaults, `urlPathType: RegExp` plus `storage` gets both, a subclass without options is unchanged, a mismatched schema value is rejected. The origin is already validated by `assertBaseUrl`, so `seed()` costs string page objects nothing. |
| 2026-10-09 | Fixture: a `/teststorage` route (GET and POST) with a startup snapshot, a link and a form POST to the second origin `http://127.0.0.1:9000`, a COOP variant and a `/teststorage/sw.js` worker; `testStorage` and `testStorageSecond` page objects; the nine helper tests move from `testPage.spec.ts` to `sessionStorage.spec.ts`. | Same structure as plans 1.1-1.2 and 1.3-1.4; the second origin needs no server change because express listens on all interfaces. |
| 2026-10-10, amended 2026-10-19 | One seed registry per `Page`, shared by every helper on it: one init script per pending origin, one set of listeners, entries merged per origin across helpers. Rejected: per-helper registries. | Several page objects commonly share an origin; one registry gives their merged entries one script and one disposal. |
| 2026-10-10 | A seed still pending when the page closes fails the test with a message naming the origin and the keys and saying to remove the seed call or navigate before the test ends; raised only when `test.info()` is available and reports a passed status with no errors. Rejected: staying silent; a report annotation only; a `cancelSeed` escape hatch. | An error thrown in a `page.on("close")` listener fails a test whose body passed, and `test.info()` is readable there with `status` and `errors` (verified in the harness), so the failure is loud, never doubles an existing one, and never fires for a skipped or timed-out test or outside a test. Seeding without navigating is a mistake and the fix is to not call `seed`; no real use for cancelling was found, and adding a method later is non-breaking while removing one is not. |
| 2026-10-10, amended 2026-10-19 | The `seed` call site is captured and carried by every seed-related error. | Errors thrown from listeners would otherwise point into POMWright. |
| 2026-10-09 | `docs/v3/session-storage.md` documents the codecs with worked user codecs (`number()`, `base64Json<T>()`, an `xml<T>()` wrapper), multi-origin flows, the service-worker limitation with every fix and its consequences, the referrer and unsupported-method caveats of `seed`, and a 2.x migration with usage cases side by side. | Every limitation found in review is a documented behaviour, not a surprise. |

## Plan 1.6-1.8: registration guards, frames, and update semantics ([PLAN-1.6-1.8-REGISTRATION-AND-FRAMES.md](PLAN-1.6-1.8-REGISTRATION-AND-FRAMES.md))
